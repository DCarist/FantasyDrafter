# Start/sit recommendation redesign plan

## Context
The Team view currently recommends some bench players over established starters in a dynasty league, including Jacob Saylors over Jahmyr Gibbs and Garrett Nussmeier over Justin Herbert. Review the current calculation and replace misleading lineup advice with a defensible weekly start/sit decision while preserving league-specific eligibility.

## Findings
- Root cause: `scripts/in_season_manager.py:get_team_view_data` compares `float(score or (1000 - int(rank)))`. Valid normalized score `0.0` is false, so low-ranked bench players use a different 1000-rank scale: Jacob Saylors `redraft=347`, dynasty fallback score `0` → **653**, Garrett Nussmeier `dynSF=353.3`, score `0` → **647**. Jahmyr Gibbs `dynSF=9` → **97.3** and Justin Herbert `dynSF=12` → **96.3**. The current `UPGRADE_START` rule (>15) therefore produces both reported swaps despite ranking them much lower. These four players and their slots appear together on the latest team-4 snapshot in `data/in_season_store.db` for `We Like Sportz Dynasty League`; this is a real mixed-scale bug, not a matchup calculation.
- `get_team_view_data` issues `INJURY_SUB` for any OUT/IR starter without slot eligibility, otherwise checks the starter's `pos` rather than assigned FLEX/SUPERFLEX `slot`, breaks on the first match per bench player, and truncates unsorted advice to five. There is no current-week projection or opponent in the upgrade branch; its “score/matchup edge” message is false. The same zero-as-missing expression occurs in drop-candidate ranking and needs correction without redefining dynasty trade value.
- `js/roster-manager-ui.js:renderTeamView` displays the unstructured advice message as Lineup Hazard/Matchup Recommendation and separately shows long-term Rank/Score; it does not show week, projected points, evidence, or data freshness. `js/roster-manager-state.js:fetchTeamView` may retain previously cached rosterData after a failed league switch; do not present such advice as current for the selected league.
- Sleeper's observed `https://api.sleeper.app/projections/nfl/2026/3?season_type=regular` response has week/season/player_id and per-player projected `stats`, and `https://api.sleeper.app/v1/state/nfl` reports season/week. Week-3 sample: Gibbs `pts_half_ppr=20.89`, Saylors `1.24`, Herbert `16.5`, Nussmeier has no points projection. The reported dynasty league has `scoring_settings.rec=1.0` plus unprojected yardage/long-TD bonuses despite its top-level `scoring='half'`; do not use that label or dynasty asset ranking to decide weekly points. The projections endpoint is observed working but not in Sleeper's main public API documentation; transport/schema failure must abstain, not invent estimates.
- The local `player_game_logs` table has completed weeks 1–2, not forecasts; `tests/in-season-manager.test.mjs` contains the closest Team view fixture and pins the old first injury advice. `scripts/in_season_manager.py:align_starters_to_slots` provides normalized starter slot names; roster league settings include Sleeper `roster_positions`/`scoring_settings` and ESPN `rosterSlots`/`scoring_settings.scoringItems`. ESPN stat ID meanings are documented in `https://raw.githubusercontent.com/cwendt94/espn-api/master/espn_api/football/constant.py`; unknown or non-projectable scoring items cannot be treated as a default PPR score.

## Decisions
- Optimize this week's projected points, not dynasty value, in every connected league.
- Use live weekly projections; when absent or materially unprojectable, withhold ordinary swap recommendations but preserve availability alerts.
- Apply exact league scoring where the projected inputs support it; if unprojected custom bonuses could change the comparison, abstain rather than silently approximating. The reported league has such bonuses.

## Approach
1. **Remove the proven mixed-scale bug before introducing a new ranking signal.** In `scripts/in_season_manager.py:get_team_view_data`, delete the current nested bench/starter score-comparison loop and its `score or (1000-rank)` expressions. Keep `calculate_player_rank_and_score` and the existing `rank`/`score` roster fields for dynasty/redraft asset display, but never use them for weekly lineup advice. Change the analogous `drop_candidates` sort to use `score` when it is not `None` (zero is valid), otherwise `0.0`; retain the drop section's separate asset ranking rather than blending it into start/sit.
2. **Resolve one live, explicitly dated weekly projection snapshot for the requested league.** Add `get_weekly_projection_context(league: dict[str, Any]) -> dict[str, Any]` in `scripts/in_season_manager.py`: fetch `https://api.sleeper.app/v1/state/nfl`, require `season_type='regular'`, `1 <= week <= 18`, and matching `league['season']`; then fetch `https://api.sleeper.app/projections/nfl/{season}/{week}?season_type=regular`. Validate top-level list and each useful row's `season`, `week`, `season_type`, `player_id`, `stats` dictionary; index only that week by Sleeper player ID. Use the existing `urllib.request` pattern from `sync_nfl_weekly_stats` (10-second timeout and User-Agent), cache state and indexed projections **in process** for 30 minutes, keyed by `(season, week)`, with a lock for concurrent server requests; no new DB table or dependency. An expired cache, HTTP/JSON/schema failure, empty feed, off-season, or league-season mismatch yields `status='unavailable'`, never old-week or synthetic points. The endpoint is observed working but undocumented in Sleeper's main guide, so this abstention is mandatory if it changes.
3. **Identify and score players in the league's actual rules, not its dynasty label.** Implement `score_weekly_projection(stats: dict[str, Any], league: dict[str, Any], pos: str) -> tuple[float, float] | None` returning conservative lower/upper weekly-point bounds, or `None` when unsupported. Classify scoring keys by offensive (QB/RB/WR/TE), kicker, and defense; only apply a key to an applicable position (e.g. `pts_allow_*` is DST-only, `fgm_*` K-only, `pass_yd` potentially any offensive position); don't let a defense rule suppress an RB. For Sleeper leagues, multiply projected numeric per-stat values by applicable `settings.scoring_settings` weights; never select `pts_half_ppr` from top-level `scoring='half'` when `scoring_settings.rec` differs. For ESPN, translate nonzero applicable `settings.scoring_settings.scoringItems` using the stat meanings at `https://raw.githubusercontent.com/cwendt94/espn-api/master/espn_api/football/constant.py`: `3=pass_yd,4=pass_td,19=pass_2pt,20=pass_int,24=rush_yd,25=rush_td,26=rush_2pt,42=rec_yd,43=rec_td,44=rec_2pt,53=rec,63=fum_rec_td,72=fum_lost`; bonuses `16=pass_td_50p,18=bonus_pass_yd_400,36=rush_td_50p,38=bonus_rush_yd_200,46=rec_td_50p,57=bonus_rec_yd_200`. Apply `pointsOverrides` for the ESPN position ID where present (QB=0,RB=2,WR=4,TE=6,DST=16,K=17), else `points`. K/DST items map only where the feed represents their exact projected stat (e.g. `77=fgm_40_49,86=xpm,99=sack`); if a 50–59 vs 60+ split or blocked-return TD is unavailable, abstain for that K/DST. For both platforms, unknown nonzero applicable scoring keys/IDs, missing required numeric stats, non-finite values, or unbounded missing events return `None`; do not coerce absent stats to zero or substitute generic `pts_*`. For once-per-game unprojected bonuses (`bonus_*_yd_100/200/300/400`, `bonus_rush_att_20`, long-TD bonuses; ESPN counterparts), keep base score and add `[min(0,weight),max(0,weight)]` per possible bonus; where a long-TD bonus can repeat, use its available projected TD count as upper bound or abstain. A regular upgrade needs guaranteed `bench_lower - starter_upper >= 3.0`; overlapping bounds abstain. Numeric zero is a valid projection only with complete usable stats. Missing unexpected applicable stats means fewer recommendations, never an estimated precision claim.
4. **Rebuild legal, non-conflicting advice in `get_team_view_data`.** Preserve `align_starters_to_slots` and use its assigned `slot`/`lineupSlot` (not player `pos`) for direct-swap eligibility: QB→QB; RB→RB; WR→WR; TE→TE; RB/WR/TE→FLEX; QB/RB/WR/TE→SUPERFLEX; K→K; DST/DEF→DST; normalize `OP`/`SUPER_FLEX` and honor ESPN restricted FLEX slot IDs 3 (RB/WR) and 5 (WR/TE) via existing `lineupSlotId`. Exclude taxi/IR players entirely; never recommend benched players on bye, OUT/IR, without an NFL team, or with already-started games. Use Sleeper ID directly for Sleeper snapshots; for ESPN, resolve a **unique** `normalize_name` + position + NFL-team match from `load_sleeper_players_cache` (never equate ESPN and Sleeper numeric IDs); ambiguous/unmatched identities abstain. Prefer current feed injury status, then the dated `data/players-data.json` injury if current-day, then roster injury as an *unconfirmed warning*; normalize status case. OUT/IR and confirmed current-week bye starters create high-priority availability hazards even when no usable projection or legal bench replacement exists; mark questionable/doubtful as caution rather than auto-sit. Current-week byes come from matching-season cached `nfl_team_schedules` or the player bye, never last year's week; if game start times are known from schedule, do not propose moving already locked starters/bench players; if unknown, omit a specific swap rather than asserting lineup eligibility. For available starters, generate legal direct swaps and select upgrades only when guaranteed gain ≥3.0. For OUT/IR/bye starters, select the eligible active bench player with highest **lower-bound** points without requiring the 3-point upgrade margin; absent a verified candidate, keep a starter-only hazard. Sort hazards first, then guaranteed gain descending, then names; greedily select at most one swap per starter and per bench player and at most five advice cards. Never drop a distinct unavailable-starter hazard merely because swap cards fill the five slots: cap swap cards to the remaining room after hazards, and if there are >5 hazards show their total count. Do not attempt multi-slot lineup rearrangements or mutate platform lineups.
5. **Expose evidence and abstention in the Team surface.** Return `recommendation_context: {season, week, source, fetched_at, status, reason}` from `get_team_view_data`; use `status='ready'|'partial'|'unavailable'` and reason codes `SOURCE_UNAVAILABLE`, `SEASON_MISMATCH`, `UNSUPPORTED_SCORING`, `MISSING_PLAYER_PROJECTION`, `NO_SAFE_EDGE` as applicable. Replace opaque `message`-only advice with `type` (`INJURY_SUB`, `BYE_SUB`, `UPGRADE_START`, `LINEUP_HAZARD`), `severity`, `starter_player`, `starter_slot`, optional `bench_player`, optional `starter_points`/`bench_points` as `{lower, upper}`, optional `guaranteed_gain`, and a short `reason` (`OUT`, `IR`, `BYE`, or `PROJECTED_EDGE`). Update the only consumer `js/roster-manager-ui.js:renderTeamView` to show a Week N/Sleeper timestamp/source label, name + slot, point estimate/range and safe gain when present, and a clear “No verified weekly swap” / “Weekly projections unavailable” notice on abstention; distinguish unsupported scoring from offline feeds using reason codes. Label the roster's old `Score` column as long-term rank score so it is not mistaken for weekly fantasy points. Escape all new names/text with existing `esc`; style within existing `.advice-card` block in `css/draft-board.css`. In `js/roster-manager-state.js:selectLeague`/`fetchTeamView`, do not render cached advice for a different `league_id` or while `isServerOnline=false`; allow same-league cached roster with an explicit stale-advice notice. The `/api/manager/roster` route in `server.py` already forwards the data and needs no contract change.

## Assumptions & contingencies
- The currently selected dynasty league is `We Like Sportz Dynasty League` in the local read-only snapshot; the engine nevertheless applies to every connected league. A different local league or season at execution time must use its own settings/current week, not hard-coded team IDs or 2026/week 3.
- Exact-or-abstain for custom bonuses is deliberate: the user prefers fewer credible swaps over guessed advice. If a scoring item cannot be mapped and bounded with observed provider stats, show an unavailable/partial explanation, never revert to long-term rankings or broad PPR approximations.
